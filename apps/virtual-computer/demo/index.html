Virtual Computer PoC

Kerangka PoC — bukan produksi. Halaman statis: buka langsung dari berkas, tanpa build dan tanpa server.

Kontrol

Belum dipanggil. Cek API akan memanggil GET <base>/health.
Belum dipanggil. Buat sesi demo akan POST {"bot_id":"demo-bot"} ke <base>/v1/sessions.

Kedua tombol memakai fetch biasa dan menulis jawabannya lewat textContent; bila kontrol API belum jalan, pesan gagalnya muncul di kotak di atas, bukan di konsol.

Semua kotak di atas digambar dengan CSS: tidak ada tangkapan layar, berkas gambar, atau font eksternal. Desktop ini hanya ilustrasi tata letak, bukan sandbox yang benar-benar berjalan. State sesi asli nanti tinggal di volume /home/bolu (profil browser di /home/bolu/profile), bukan di sini.

Endpoint kontrol API

Method Path Body Response
GET /health — Liveness kontrol API; dipakai tombol Cek API.
POST /v1/sessions {"bot_id":"..."} Pastikan/buat sesi sandbox untuk bot itu; balasannya JSON status sesi.
GET /v1/sessions/:bot_id — Status sesi.
DELETE /v1/sessions/:bot_id — Hentikan sesi.
POST /v1/sessions/:bot_id/screenshot — image/png — tangkapan layar stub. GET pada path yang sama juga dilayani, supaya sebuah <img> bisa menempelkannya; POST tetap jalur resminya.
POST /v1/sessions/:bot_id/click {"x":0,"y":0} Klik pada koordinat di dalam layar sandbox.
POST /v1/sessions/:bot_id/type {"text":"..."} Ketik teks ke jendela yang sedang fokus.
POST /v1/sessions/:bot_id/exec {"command":"..."} Stub: perintah hanya digemakan, tidak pernah dijalankan di host.

PoC ini tidak mengirim token atau kredensial apa pun: seluruh permintaan hanya ke base URL yang diketik di atas, dan host secrets disuntikkan oleh control plane saat runtime.

Virtual Computer PoC — skeleton. Endpoint dan mock di halaman ini menggambarkan kontrak, bukan implementasi sandbox yang sudah jadi.
